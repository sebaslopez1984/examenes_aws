 TEMAS A REFORZAR
----------------------------------------------------------
- Almacenamiento: EFS vs EBS vs S3 vs Glacier (clases y casos de uso)
- Modelo de responsabilidad compartida (AWS "del" cloud / cliente "en" el cloud)
- Route 53: politicas de enrutamiento (failover, weighted, latency, simple)
- Alta disponibilidad por defecto (DynamoDB, EFS) vs single-AZ (Redshift, EBS, Instance Store)
- VPC Endpoints: Interface (PrivateLink, la mayoria de servicios) vs Gateway (solo S3 y DynamoDB)
- Estrategias de DR (Backup&Restore < Pilot Light < Warm Standby < Multi-site Active-Active)
- Clases S3 y tarifas de recuperacion (Standard e Intelligent-Tiering sin fee; IA y Glacier con fee)
- Servicios de IA: Translate (texto), Transcribe (voz->texto), Polly (texto->voz), Rekognition (imagen/video)
- Serverless: Lambda y Fargate (sin gestionar servidores)
- Modelo de precios EC2: Reserved (uso estable) vs Spot (interrumpible) vs On-Demand
- IAM Role para dar acceso de un servicio AWS a otro (nunca access keys en codigo)
- Global Accelerator (IPs estaticas, TCP/UDP no-HTTP) vs CloudFront (cache de contenido web)
- WAF (capa 7: SQLi, XSS) vs Shield Advanced (capas 3/4, equipo DRT)
- Herramientas de costos: Pricing Calculator (estimar antes), Cost Explorer (analizar historico), Budgets (alertas)
- Tipos de almacenamiento: S3 (objetos), EBS (bloques), EFS (archivos NFS)
- Config (historial de config de RECURSOS) vs CloudTrail (acciones/API de USUARIOS)
- Health Dashboard: Service Status (publico global) vs Your Account (personalizado, tus recursos)
- Well-Architected: 6 pilares (Exc. Operativa, Seguridad, Fiabilidad, Eficiencia Rendimiento, Optim. Costes, Sostenibilidad). Escalabilidad/Disponibilidad/Elasticidad NO son pilares
- Planes de Support: Developer (email), Business (telefono 24x7 mas barato), Enterprise On-Ramp, Enterprise
- Amazon MQ (migrar brokers ActiveMQ/RabbitMQ existentes) vs SQS/SNS (apps nuevas)
- Amazon EMR para big data (Hadoop/Spark/Hive)
- Session Manager (shell sin abrir puertos ni IP publica) vs EC2 Instance Connect (necesita puerto 22)
- Acceso a servicios AWS: Console, CLI, SDK
- Servicios gratis (IAM, Auto Scaling, CloudFormation, VPC); solo pagas los recursos que provisionan
- Controles compartidos: parches, configuracion y formacion (AWS y cliente, cada uno en lo suyo)
- EventBridge (bus de eventos) vs SQS (cola) vs SNS (pub/sub) vs Step Functions (flujo de pasos)
- Control Tower = entorno multi-cuenta con guardrails (landing zone)
- Hibrido (on-premises): Systems Manager y CodeDeploy funcionan sobre servidores locales
- IAM: usuario = access keys (largo plazo); rol = credenciales temporales; grupo y politica no tienen credenciales
- Dedicated Host (licencias por socket/nucleo, BYOL) vs Dedicated Instance (solo aislamiento)
- AWS Budgets (costo, uso, RI, Savings Plans; real y previsto) vs CloudWatch Billing Alarm (solo costo real)
- Outposts (AWS en tu datacenter) vs Wavelength (5G)
- Certificados: ACM (importar/gestionar) e IAM; no Secrets Manager ni Cognito
- Permisos S3: politica de bucket (recurso) + politica de usuario IAM (identidad)
- Plan Enterprise: TAM, IEM, revisiones Well-Architected y de operaciones
- Redshift = data warehouse (OLAP) vs RDS = transaccional (OLTP)
- Firewalls: Security Group (instancia, solo allow), NACL (subred, allow/deny), WAF (capa 7), Shield (DDoS), Network Firewall (toda la VPC)
- Trusted Advisor: si Auto Scaling no lanza instancias, mirar Limites de servicio y Rendimiento
- IAM: la POLITICA define los permisos (el que); usuario/grupo/rol son el quien. Rol = identidad temporal que se asume
- EBS: gp = uso general, io = bases criticas, st1 = secuencial/streaming/big data, sc1 = el mas barato. Instance Store = rapido pero temporal
- Storage Gateway: ampliar almacenamiento local (hibrido) con baja latencia
- Amazon Connect (call center) vs Chime (reuniones internas); AppStream (una app) vs WorkSpaces (escritorio)
- Reserved Instances: se compran para EC2 y RDS
- Costos en S3: almacenamiento, salida a internet, solicitudes y transiciones; subir datos es gratis
- Seguridad: Macie (PII en S3), GuardDuty (amenazas), Inspector (vulnerabilidades), Firewall Manager (reglas centralizadas multi-cuenta)
- S3 "rara vez accedido pero recuperacion instantanea" = Standard-IA (Glacier Flexible/Deep tardan minutos u horas)
- Planes de Support por tiempo de respuesta: Enterprise <15 min, On-Ramp <30 min, Business <1 h. TAM / IEM / revisiones = Enterprise
- Pinpoint (multicanal + medir participacion) vs SES (solo email) vs SNS (pub/sub y push)
- Security Group: origen/destino = CIDR, lista de prefijos u otro SG; no dominios ni ID de instancia
- Replicar a otra region: una EC2 = AMI copiada; toda la infra = CloudFormation. DR de EC2 = AMI + snapshots EBS
- RI: formas de pago = todo por adelantado, parcial y sin anticipo (No Upfront)
- CAF Gobernanza incluye gestion de riesgos y gobernanza/curacion de datos
- Costos vs Rendimiento (Well-Architected): mirar si pesa el presupuesto o el ajuste al requisito
- Savings Plans (flexibles: familia, tamano, SO, region) vs Reservadas (atadas a tipo y region)
- Internet Gateway (subred publica) vs NAT Gateway (subred privada sale a internet)
- Parches EC2: SO host = AWS; SO guest y apps = cliente
- Cognito Identity Pool (credenciales temporales AWS, incl. invitados) vs User Pool (login de la app); Directory Service = Active Directory
- EC2 detenida (Stopped): solo se cobra el EBS
- ECS (orquesta) vs Fargate (sin administrar servidores)
- Planes de Support: AWS los reestructuro a fines de 2025; los bancos usan nombres clasicos. Health Dashboard (Your Account) esta en todos los planes
- Redshift = data warehouse: fallada 3 veces (udemy_1.2, 1.4, 1.5), repasar si o si
